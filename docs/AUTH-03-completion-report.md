# AUTH-03 — Email OTP verification

## Scope

AUTH-03 adds email verification for accounts created as `PENDING_VERIFICATION`.
It does not implement password reset, MFA, global rate limiting, or JWT changes.

## Persistence and security

- `V20260923090100__hp_auth03_email_otp.sql` creates `uteexpress.otp_tokens` with a
  non-cascading user foreign key, `EMAIL_VERIFICATION` purpose check, timestamp and
  attempt constraints, and a latest-token lookup index.
- Codes are six decimal digits generated by `SecureRandom`; leading zeroes are valid.
- PostgreSQL stores only lowercase HMAC-SHA256 output. The MAC input includes user ID,
  server-owned purpose, and code. Comparison uses `MessageDigest.isEqual`.
- `OTP_PEPPER_BASE64` must decode to at least 32 bytes. No production default exists.
- Default TTL is 10 minutes, maximum failed attempts is 5, and resend cooldown is
  60 seconds. These values are configured under `uteexpress.security.otp`.
- Verification uses pessimistic locks and one transaction for token consumption plus
  `PENDING_VERIFICATION -> ACTIVE` and `email_verified_at`.

## Registration and mail

The registration transaction commits before OTP issuance. OTP persistence commits
before mail delivery, so SMTP failure never removes the user. Public responses remain
generic, and resend continues to work for an eligible account.

Spring Mail reads `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`,
`MAIL_FROM`, `MAIL_SMTP_AUTH`, and `MAIL_STARTTLS`. Automated tests mock
`JavaMailSender`; they never send Internet email. For local testing, point the same
variables at Mailpit/MailHog or a real SMTP service and keep credentials outside Git.

## HTTP flow

1. Successful `POST /register` redirects to `/verify-otp` and attempts delivery.
2. `GET /verify-otp` renders the shared Thymeleaf form.
3. `POST /verify-otp` validates the latest usable token and remains CSRF protected.
4. Success consumes the token, activates the account, and redirects to
   `/login?verified=true`; it does not automatically authenticate the user.
5. `POST /verify-otp/resend` is CSRF protected, enforces cooldown, and always gives an
   enumeration-safe public response.

The identifier can resolve a persisted normalized email or username. The mail recipient
always comes from the persisted user. Unknown, `ACTIVE`, `LOCKED`, and `DISABLED`
accounts are indistinguishable through public resend behavior.

## Verification

- Unit/MVC tests cover SecureRandom formatting, HMAC domain separation, key validation,
  constant-time matching, mail composition, SMTP failure, CSRF, generic responses, and
  no OTP echo.
- PostgreSQL 17.6 Testcontainers tests cover Flyway/Hibernate validation, constraints,
  attempts, expiry, cooldown, resend, one-time use, status boundaries, concurrent
  verification, and registration → verification → JWT login.
- Required commands: `.\mvnw.cmd clean test`, `.\mvnw.cmd package`, and
  `.\mvnw.cmd -Ppostgres-it verify`.
